Dino-runner: what is decided, what is proposed, what is built

This page is not the spec. It summarises the design dumps V0, V1 (with the author's answers to Q1–Q12) and V2. If this page and those files disagree, the files win.

No gameplay code exists yet. The repository contains the Base App template, renamed to Dino-runner. Every game rule below is a design statement, not a description of running software. Nothing has been deployed to any store.

The design is pre-plan. Questions #13–#26 are unanswered. They are listed in Open questions.

1. What it is and is not Decided

One input (hold/release) → shared core loop + one obstacle stream → per-dinosaur collision rules → score.
Dino-runner does not reuse the Chrome game's art, name or night-mode features in this iteration.

DoesAn endless runner on the Chrome offline-dinosaur loop (auto-run, speed ramp, gaps, collision, score). The player picks one of three dinosaurs, each with its own rules. All three are available from the start (Q10).
Does notCopy the original sprite, or use "Chrome" or "Google" in the title, icon or screenshots (Q12). Night mode, the score flash and the clear-time start are not in this iteration (Q11). It is not "a reskin with a character select" (V1 S1).
Ships toGoogle Play, web and iOS (Q9). Under what store title is open (Q24).
Not settled VerifyCollision mechanism, stream mix, meter numbers, stack, score storage, art style. See Open questions.

2. The three dinosaurs Decided

All three share one input and one obstacle stream. Each acts on one obstacle class and ignores another. The world has two bands: a lower band (cacti, rocks, the grounded T-Rex, the triceratops, a diving pterodactyl) and an upper band (the cruising pterodactyl, a jumping T-Rex, flyers). Source: V1 answers Q1, Q3, Q4, Q5; table from V2 §3.

DinosaurInputMust act onIgnoresDies when
T-RexHold to jump; variable height. No duck (Q2). Fast-drop dropped Verify (Q22)Cacti, rocks (jump them)Flyers, while on the groundIt touches a cactus or rock, or touches a flyer while airborne
PterodactylCruises at the top; hold to dive (the T-Rex's jump, inverted)Flyers (dive under them)Cacti, rocks, unless divingIt touches a flyer, or a ground obstacle while diving
TriceratopsCannot jump. Hold to charge, which drains the cactus meterRocks (charge through them)Flyers (upper band, Q5)It meets a rock without charging, including with an empty meter (Q8)

Triceratops specifics (V0, Q6, Q8): it eats cacti to refill the meter. While charging it cannot eat cacti, but cacti do not hurt it. The meter starts full. It is shown in the upper band, and only for the triceratops. Cacti can never kill it.

The reference implementation gives the pterodactyl a head start. The Chromium T-Rex has a per-character invertJump flag (trex.ts:27,76, honoured at :474,500,509-523), left over from removed alt-game characters. A downward jump from a top baseline is already written (V2 verdict on Q4). The repo contains no Chromium code yet.

3. One obstacle stream, three dinosaurs Proposed

The same three obstacles, cactus → rock → flyer, arrive one after another. They are traced once per dinosaur. Rows read Number · Owner · Action · Data. "Owner" names a design component; none of them exists in code yet (see §6). Each row carries the status of the rule it relies on.

Rows are written in the present tense for readability. They describe intended behaviour, not running code. File references such as trex.ts and obstacle.ts point into the Chromium source (§9), not into this repository.

One stream for every dinosaur makes difficulty depend on the mix. At 1 cactus : 2 rocks plus a few flyers, the T-Rex acts on almost everything and the pterodactyl on almost nothing. The flyer share is open (Q15), and so is whether the mixed board should be fair across dinosaurs (Q20).

4. Bands: rule, not geometry Proposed

The author's two-band model (Q4) does not survive the original's real hitboxes. A held jump's apex box sits at y 3–50, above the high flyer's box at y 59–78. A short hop sits inside that row for 22–24 of its 26–28 airborne frames. "Airborne = upper band" is therefore true for some jumps and false for others, and the result shifts with screen aspect ratio (V2 S1, trex.ts:86-91,469,516-520).

Proposed (Q13): decide collisions by band membership. Airborne T-Rex or diving pterodactyl = the other band; collide with anything in that band that overlaps in x. Arcs are drawn for looks only. Variable height then controls airtime, not clearance (Q14).

5. Triceratops meter economy Proposed

The stated loss conditions are skipping cacti and over-charging. They only hold if no sequence is unsurvivable with perfect play. Two things in the current wording break that (V2 S2):

Generator at 1 cactus : 2 rocksLongest rock runRock share
Independent random draws (as worded, Q7)Unbounded: average 11.3 per 200-obstacle game, 99th percentile 21, worst seen 430.667
Chrome's repeat cap of 2 (horizon.ts:299-305)20.556 (forces 1:2 toward 4:5)
Bag shuffle [C,R,R] Proposed4 (bag C,R,R then R,R,C)0.667

Figures come from a 200,000-run Monte Carlo in V2 (mc.js, job scratch, not in the repo).

Cost basis. Time-based drain makes a cactus worth 1.32–1.37× more rocks at speed 13 than at 6. Pixel-based drain goes the other way (0.61–0.63×). A fixed cost per rock keeps "one cactus = 2–3 rocks" true at every speed. A small drain while the button is held still punishes over-charging (Q17).

6. Stack and ownership Verify

The stack question (Q19) is formally open, and the repository already leans one way. V2 recommended TypeScript canvas wrapped in Capacitor (D7). The project was then bootstrapped from Base App, which is Expo SDK 54 and ships a Phaser engine: Phaser runs directly on web and in an offline WebView on Android and iOS. That gives a TypeScript-canvas game inside an Expo shell, a third route V2 did not weigh. Until Q19 is answered, no engine is chosen: do not write game code against Phaser, the game-loop engine, or Capacitor.

7. Which code blocks are real Current

The design has no wire contract and no JSON schema. This page therefore shows no JSON, and every game rule above is prose or a table, not an API.

The one real contract in the repo is the host↔game message boundary of the Phaser engine. The block below is copied verbatim from src/engines/phaser/bridge.ts at 5262eea. It is Base App's demo contract: the bounce event belongs to the demo scene, and the game's own events have not been designed.

Real file, verbatim excerpt — demo contract, not the game's

/** Game → host. */
export type GameEvent = { type: 'ready' } | { type: 'bounce'; count: number } | { type: 'log'; message: string };

/** Host → game. */
export type HostCommand =
  | { type: 'pause' }
  | { type: 'resume' }
  | { type: 'restart' }
  | { type: 'settings'; sound: boolean; volume: number };

8. Public and private data Current Proposed

Repository facts are Current. The player-data line is design only.

  • The repository is public (github.com/ivan-i1/Dino-runner). Anything committed is published.
  • Never committed: credentials/ (Android upload keystore and its passwords), keystores and .env.local. All are gitignored (CLAUDE.md). Only templates are tracked: credentials.example/ and .env.example.
  • Public by construction: EXPO_PUBLIC_API_URL ships inside the bundle (README → Configuration). The game design states no backend.
  • Player data: best scores. Local only is Proposed (Q21). No online board works on web without a third party (V2 Q10 verdict).
  • Licensing: the repo is MIT. Any Chromium code that gets ported is BSD-3-Clause and must keep its notice (V1 A5).

10. Shipping prerequisites Verify

  • Apple Developer Program ($99/yr). A team ID in another project does not prove membership (V2 U5, Q23).
  • Play closed test: 12 testers for 14 days if the Play account is personal and was created after 2023-11-13. This is the longest wall-clock item (V2 U5, Q23).
  • Name: two live Play listings are titled exactly "Dino Runner". Apple allows a name for one app per localization, and Guideline 4.1 bars "minor changes" to another app's name (V2 Q12 verdict, Q24).
  • Apple 4.3(b) spam risk: dino runners are a crowded genre. The three-dinosaur mechanics are the differentiation, so a T-Rex-only first release is the riskiest submission (V2 U6, inferred).
  • Device verification: rendering, input feel and audio can only be checked on a device or simulator. The automated gates reach pure logic only (CLAUDE.md).

11. Deferred Deferred

Out of this iteration (Q11): night-mode inversion every 700 points, the score flash and sound every 100 points, and the original's clear-time start. V2 adds one correction: some grace period before the first obstacle is still needed in any minimum build.
